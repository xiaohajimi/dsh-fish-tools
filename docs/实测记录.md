> 所有数字来自 2026-11-19 ~ 11-20 的真实运行。
> 环境：RTX 5070 Laptop 8 GB / Ryzen 9 7845HX / 24 GB RAM / Win11 / 驱动 621.24

## 一、显存频率与节流

```
标准频率：12001 MHz（nvidia-smi 口径）= 1500 MHz（GPU-Z）= 24 Gbps = 384 GB/s
省电档  ：9001 MHz（掉 25%）
超频档  ：13001 MHz（+8.3%，三星 GDDR7 可承受）

节流原因：nvidia-smi -q -d PERFORMANCE 里的 clocks_event_reasons
          "Reliability: Active" 会在满载时把显存压到 9001
          改设置清不掉，只有重启能解除
```

**实测影响**：锁 12001 与掉 9001，训练速度差 < 10% → 瓶颈不在带宽。

## 三、几个会要命的坑

### 1. `paged_adamw_8bit` 保存优化器状态会死锁

```
现象：第 50 步保存时卡死，GPU 0%、磁盘 0 MB/s，Kill 不掉
解法：TrainingArguments(save_only_model=True)
     只存 adapter（169 MB），不存 optimizer.pt
     续训用 --init-adapter 热启动，不恢复优化器状态
```

### 2. `save_only_model` 是 TrainingArguments 的字段，不是 Trainer 的参数

```
❌ Trainer(..., save_only_model=True)
   → TypeError: unexpected keyword argument
✅ TrainingArguments(..., save_only_model=True)
```

### 3. 4bit 之后 LoRA 挂错层，训练“成功”但完全没学到

```
现象：loss 正常下降，保存成功，推理效果和没训一样
原因：bnb 把 Linear 包成 ClippableLinear(linear=Linear4bit)
      正则 .*\.linear$ 匹配不到，target_modules 静默为空
检查：训完打印可训练张量数，必须 > 0
```

### 4. transformers 5.x 没有 warmup_ratio

```
改成 warmup_steps（数值自己算：总步数 × 比例）
```

## 四、硬件监控的坑

```
· AMD 平台读不到 CPU 温度（WMI 热区空、Get-Counter 无实例）
  → 需装 LibreHardwareMonitor 并开 WMI 共享
· nvidia-smi 的 temperature.gpu 返回浮点（44.16），直接 int() 会抛异常
· 每 60 秒调一次 nvidia-smi 对训练速度的影响 < 2%（实测）
```
