## 一、USB vs Wi-Fi：链路实测（1 GB 文件）

```
USB（hdc file send，设备序列号 5KLBB25B07201236）
  4.64 MB    → 38 MB/s      小文件，被启动开销拉低（不算数）
  100 MB ×3  → 75.8 / 86.0 / 82.1 MB/s
  1 GB       → 110.9 MB/s（9.24 秒）
  1 GB 并发  → 137.1 MB/s（7.83 秒）
Wi-Fi（Windows 移动热点 → 平板，hdc -t 192.168.137.54:37303）
  1 GB       → 30.9 MB/s（33.18 秒）
  1 GB 并发  → 41.3 MB/s（26.00 秒）
双路并发（各 1 GB，共 2 GB）→ 26.55 秒，聚合 77.1 MB/s
Wi-Fi ping：58 / 67 / 90 / 104 ms（4 包 0% 丢包）
```

**读法**：并发时两条都比单跑快，说明瓶颈不在链路带宽，而在平板存储写入 / hdc 拷贝。
所以"双链路叠加带宽"对推理没有意义；有意义的是主备切换与手动指定。

## 二、8 GB 显存下训练会在什么时候炸

```
配置：QLoRA 4bit，seq 512，accum 8，bs 1，duty 0.85
崩溃：step 78 / 265，RuntimeError: CUDA error: out of memory
栈位置：model forward → create_masks_for_generate → masking_utils.sdpa_mask
崩溃前显存：7693 / 8151 MiB（只剩 458 MB）
同时占显存的程序：LM Studio（约 300~600 MB 动态）、Steam webhelper、
                 NVIDIA Overlay ×2、Edge、Windows 合成器
```

**教训**：8 GB 卡上跑训练，**必须给显存留 ≥ 15% 余量**（这里不到 6%），
否则跑着跑着被任何一次波形（保存、日志、别的程序）挤爆。

## 三、三条缓解措施（已生效）

```
① --seq 512 → 448          激活内存约降 12~15%
② PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True,garbage_collection_threshold:0.8
③ 训练期间关掉 LM Studio / Steam webhelper（NVIDIA Overlay 可留）
```
