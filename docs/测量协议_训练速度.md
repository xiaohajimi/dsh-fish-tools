# 训练速度测量协议 v1.0

> 目的：让"某配置快/慢"这句话**能被人复现**。
> 定于 2026-11-20 01:25。任何速度结论必须按本协议产出，否则只标"观察值，未验证"。

---

## 一、必须控制的变量（少一个，结论就不成立）

| 变量 | 要求 | 为什么 |
|---|---|---|
| **磁盘 I/O** | 测量期间不下载、不建索引、不跑备份 | 302 MB/s 的下载会让步速慢 16%（已实测） |
| **后台进程** | 关浏览器大标签、停看门狗采样到 300 秒一次 | Edge 曾占 1 GB 内存，导致换页 |
| **起始状态** | 同一 checkpoint 热启动，先跑 1 步丢弃（warmup） | 首步含编译/分配，比稳态慢 30~50% |
| **序列与 batch** | 固定 `--seq 512 --bs 1 --accum 8` | 变一个就不是同题 |
| **duty** | 固定并记录（当前 0.97） | duty 本身改变平均速度 |
| **温度** | 起始温度 40~48°C，中途记录峰值 | 过热会降频 |
| **电源** | 必须接着电源，ChargeRate 可查 | 电池模式会限功耗 |

---

## 二、测量方法

```
每组配置：
  ① 从同一 checkpoint 启动
  ② 丢弃第 1 步
  ③ 记录第 2~4 步的 s/it（共 3 个数）
  ④ 取中位数作为该组的代表值
每组的每次测量都写进 measurements.jsonl（含时间、温度、功耗、显存频率、磁盘 IO）
```

**至少两组重复**（同一配置跑两次），两次差 >8% 视为不稳定，需查原因。

---

## 三、记录格式（机器可读，不许手填）

```json
{"ts":"2026-11-20 01:30:00","config":"std-12001","seq":512,"duty":0.97,
 "step_s":[117.2,116.8,118.0],"median":117.2,"gpu_temp":46,"power_w":25.1,
 "mem_mhz":12001,"sm_mhz":2820,"disk_mbs":2.1,"confounders":[]}
```

`confounders` 字段：测量期间若有任何非预期负载（下载、索引、系统更新），必须填进去并标"作废"。

## 六、电压轮次（2026-11-20 03:15 操作者补充）

**操作者交替跑两档电压：1.05 V 与 0.925 V，每轮切换，目的是延缓显卡老化。**

```
这意味着：同一个配置在 1.05V 轮和 0.925V 轮里速度不同
→ 任何速度对比，必须同时记录"当时是哪一档电压"
→ 否则就是拿两个变量在比（我今晚已经犯过这个错）
```

做法：

```
① 标记文件 D:\操作者专用\train\_gpu_round.txt，内容写 1.05 或 0.925
② 看门狗每 2 分钟采样时会带上 gpu_round 字段
③ 每次测速前先确认轮次，测速记录里必须写进去
④ 对比只允许同轮次内比较
```

**另：GPU 频率（SM / 显存）是解释"为什么慢"的第一证据**——
以后任何"变慢了"的判断，先报 SM 频率、显存频率、功耗、轮次，再说结论。
