# 试题基准（双层加密）

一套跨领域评测题库：**网络工程 18 题 + 安全实操 34 题**，共 52 题。
另外 100 道算法题（AtCoder）是公开题目，不在此包内。

---

## 为什么是双层

| 层 | 技术 | 作用 |
|---|---|---|
| **第一层** | AES-256-GCM | 真正的密码学保护。**钥匙不在本仓库**，只在发卷时交给被评测的模型 |
| **第二层** | C7-42 语义码（中文多义消歧） | 解开 AES 后拿到的仍是语义密文；同一串码有多解，只有懂当前语境才选得对 |

```
明文题目
  → C7-42 语义加密（中文→拼音→码表→三进制）
  → AES-256-GCM（随机 nonce，密钥 32 字节）
  → payload/*.bin
```

**所以：没有钥匙 → 解不开 AES；有钥匙 → 还要过语义关。**

---

## 包里有什么

| 文件 | 内容 |
|---|---|
| `manifest.json` | 题目清单、文件名、来源链接、**第二层密文的 SHA256 指纹**、版本 |
| `payload/*.bin` | 52 个密文块（每块 = 12 字节 nonce + AES-GCM 密文） |

**没有钥匙文件。** 这保证拿到本仓库的人（无论是人还是 AI）都无法自行解密。

---

## 完整性验证（不需要钥匙）

```python
# manifest.json 里有 sha256_of_layer2_plaintext
# 用钥匙解密全部 payload、拼成文本、算 SHA256，必须与它一致
# 一致 → 题目没被篡改；不一致 → 作废
```

本包当前指纹：见 `manifest.json` 的 `sha256_of_layer2_plaintext`。

## 答题流程（评测时）

1. 评测方把 **32 字节钥匙**（十六进制）交给被评测的模型
2. 模型解密 → 得到 C7-42 语义密文
3. 按 `04` 号规则（见下）还原拼音与词义
4. 逐题作答，**思考链与答案都写成密文**，每题附自造印记
5. 输出写入桌面 `试题基准_我的答案.txt`

### C7-42 规则（第二层）

```
中文 → 拼音（带声调） → 字母对 → 码表数字
声调 1/2/3/4 作为独立数字插在该音节后
非中文 → 前导 0 + 三位 ASCII
所有数字混流 → 逐个转三进制（满 3 进一）
0/1/2 → A/B/C，每三位一组
```

自检向量（用于验证解码器写对）：

```
明文：你好
数字：[41, 13, 3, 1, 13, 219, 3]
密文：BBBCBBBBABBBBCCABABAA
```

## 为什么这样做

明文公开会有两个问题：**版权**（网络题来自软考真题整理）和**作弊**（先看题再答）。
而单纯加密又挡不住"人类看题后喂答案给 AI"。

所以这套设计把"钥匙"和"语境"分开：
- 钥匙控制**能不能看到题**
- 语境控制**能不能解对题**
